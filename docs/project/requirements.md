# Требования и User Stories

Требования описывают текущую реализацию Mesh2D. Критерии приёмки задают проверяемые условия для поддерживаемых геометрий.

## Функциональные требования

| ID | Требование |
| --- | --- |
| FR-01 | Читать геометрию и число ячеек из JSON через CLI |
| FR-02 | Строить четырёхсторонний блок методами `ai` и `tfi` с кривыми Безье, сгущением и именами границ |
| FR-03 | Строить круг, звезду и область с отверстием методом `radial` |
| FR-04 | Отклонять инвертированные, невыпуклые и вырожденные ячейки по угловым якобианам |
| FR-05 | Выводить `cells`, `min_area`, `min_scaled_jacobian`, `max_aspect_ratio` |
| FR-06 | Экспортировать SU2, VTK и OpenFOAM `blockMeshDict` |
| FR-07 | Сохранять PNG, SVG или PDF по `--plot`; открывать интерактивное окно по `--show` |
| FR-08 | В SU2/OpenFOAM объединять шов кольцевой области и сохранять группы `inner_wall`, `outer_wall` |

## Нефункциональные требования

| ID | Требование |
| --- | --- |
| NFR-01 | Python 3.11–3.14, установка через Poetry 2 |
| NFR-02 | Воспроизводимое обучение с фиксированным seed и кеширование весов внутри процесса |
| NFR-03 | Не более одного миллиона узлов |
| NFR-04 | Обработанные ошибки CLI: сообщение `mesh2d: ...`, код завершения 2 |
| NFR-05 | Входной JSON, файл сетки и изображение должны иметь разные пути |

Глобальные самопересечения и пригодность для конкретного физического расчёта требуют отдельной проверки. Запись сетки и изображения не является общей транзакцией: ошибка изображения может произойти после экспорта.

## US-01. Построение сетки

**Как** пользователь, готовящий плоский расчёт, **я хочу** задать геометрию и разрешение в JSON, **чтобы** получить сетку без ручного размещения внутренних узлов.

Критерии приёмки:

1. Команда из README для `examples/channel.json` с методом `ai` создаёт VTK-файл.
2. Отчёт содержит 1536 ячеек, положительную минимальную площадь и положительный минимальный нормированный якобиан.
3. Граничные узлы соответствуют заданным кривым.
4. Та же геометрия принимается методом `tfi` без изменения JSON.

## US-02. Передача сетки внешнему инструменту

**Как** пользователь ParaView, SU2 или OpenFOAM, **я хочу** выбрать формат экспорта, **чтобы** использовать сетку в своём рабочем процессе.

Критерии приёмки:

1. `--format vtk`, `--format su2`, `--format foam` записывают соответствующий формат по пути `-o`.
2. Отсутствующие родительские каталоги создаются автоматически.
3. SU2 сохраняет именованные граничные рёбра; для канала используются `inlet`, `outlet`, `wall`.
4. Для кольцевой области в SU2/OpenFOAM шов объединён, имеются группы `inner_wall`, `outer_wall`.
5. Торцы OpenFOAM имеют тип `empty`; конкретные типы боковых границ и поля задаёт пользователь.

## US-03. Контроль результата

**Как** исследователь метода, **я хочу** видеть сетку и показатели качества, **чтобы** оценить результат до внешнего расчёта.

Критерии приёмки:

1. `--plot out/channel.png` сохраняет изображение с границами и показателем качества; также принимаются `.svg` и `.pdf`.
2. `--show` открывает интерактивное окно в среде с доступным графическим интерфейсом.
3. Недопустимые ячейки отклоняются до экспорта.
4. Отчёт содержит все поля FR-05; локальное качество не трактуется как доказательство пригодности для CFD.
